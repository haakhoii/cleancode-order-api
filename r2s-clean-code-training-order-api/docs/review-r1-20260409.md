## Đối chiếu với `refactor-notes.md`

### Đã cải thiện rõ

| Vấn đề trong notes | Thực tế trong code |
|-------------------|---------------------|
| **SRP** – `createOrder` làm quá nhiều việc | `OrderCommandServiceImpl` chủ yếu orchestrate; pricing ở `PricingServiceImpl`, discount ở `DiscountCalculationServiceImpl` |
| **OCP / Strategy** – if-else discount dài | Nhiều class `*DiscountStrategy` + `DiscountCalculationServiceImpl` gom qua `List<DiscountStrategy>` |
| **DIP** – gửi mail trong service | `ApplicationEventPublisher` + `OrderNotificationListener` + `NotificationClient` (Feign) |
| **ISP** – interface to có `sendEmail`, `exportCsv` | Chỉ còn `OrderCommandService` / `OrderQueryService` tách read/write |
| **Observer** – side-effect trong business | `OrderCreatedEvent` + `@EventListener` (listener swallow exception → không làm fail transaction – hợp lý với async) |
| **Magic string** | `OrderStatus`, `CustomerType`, `DiscountCode` + Bean Validation trên `CreateOrderRequest` |
| **DRY validation** | Jakarta Validation thay chuỗi if thủ công ở đầu `createOrder` |

### Còn lệch so với notes / mẫu I/O

- **Trạng thái đơn**: docs ví dụ `"NEW"`; enum hiện là `PENDING` / `PAID` / `CANCELLED` — cần thống nhất contract API/tài liệu.
- **Luật discount trong notes**: `PROMO20` chỉ khi `total >= 10_000_000`; implementation hiện **áp dụng 20% không điều kiện** (`Promo20DiscountStrategy`).
- **Số tiền mẫu**: ví dụ FREESHIP là 25_000 trong notes smell; code `FreeShipDiscountStrategy` dùng **75_000** — có thể chủ ý, nên ghi rõ trong spec.
- **VIP / NEW**: notes gợi ý mức cố định; code dùng % VIP và mức cố định khác — không sai nếu đó là spec mới, nhưng **không khớp** ví dụ training.

## Lỗi / mùi code cần sửa (quan trọng)

### 1. `NewCustomerDiscountStrategy` – sai điều kiện áp dụng

`isApplicable` đang kiểm tra `CustomerType.VIP` thay vì khách **NEW**. Hệ quả: khách VIP có thể bị cộng thêm cả “new customer” discount (và logic nghiệp vụ sai hoàn toàn).

**File:** `src/main/java/vn/r2s/training/api/service/strategy/NewCustomerDiscountStrategy.java`

```java
  public boolean isApplicable(CreateOrderRequest request) {
    return request.getCustomerType() == CustomerType.VIP;
  }
```

Cần sửa thành `CustomerType.NEW` (hoặc đúng enum nghiệp vụ).

### 2. `ApiExceptionHandler` – import `BadRequestException` sai package

Handler đang import `org.apache.coyote.BadRequestException` (Tomcat) trong khi `OrderQueryServiceImpl` ném `vn.r2s.training.api.exception.BadRequestException` → request invalid id có thể rơi vào `handleUnknown` và trả **500** thay vì **400**.

**File:** `src/main/java/vn/r2s/training/api/config/ApiExceptionHandler.java`

### 3. Xử lý lỗi không đồng nhất

- `OrderCommandServiceImpl.getCustomerByEmail` dùng `RuntimeException` thay vì `NotFoundException` (khác với layer query).
- `PricingServiceImpl` dùng `IllegalArgumentException` / `RuntimeException` cho validate và product không tìm thấy — không đi qua handler domain một cách nhất quán (400/404).

## Nhận xét nhỏ (chất lượng / mở rộng)

- **Cộng dồn strategy** (`stream().sum()`): hợp lý cho “stack” nhiều loại giảm; sau khi sửa bug NEW/VIP cần **xác nhận nghiệp vụ** (ví dụ chỉ một mã promo, hay VIP + promo được cộng).
- **Chiết khấu phần trăm trên tổng**: thứ tự (promo trước/sau VIP) có thể làm lệch vài đồng — nếu training yêu cầu khớp số mẫu trong PDF thì cần spec rõ.
- **`OrderNotificationListener`**: nội dung `"Order successfully"` chung chung; có thể giàu thông tin hơn (order id) như notes cũ — không bắt buộc nếu không nằm trong yêu cầu.
